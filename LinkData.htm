1.0    Overview

 

LinkData.DLL is the Link Standard Data reader used by the ProLink suite of tools (DynoView, CfgMgr, ScriptEdit, RevdataPLUS, etc.). This DLL allows the machine control script language access to all data written by the DOS based data loggers (Datalog, Inv), the ProLink DynoLogger.DLL, LinkLogger.DLL and other Link data providers. With this DLL installed, scripts can be written to read the native machine generated data and export that data to files of virtually any output format. This DLL is also used by the CfgMgr system and main scripts to read / process previously recorded data.

 

Companion DLLs; LinkData_VB.DLL, LinkData_VB64.DLL provides all the same functionality as the LinkData.DLL but it can be used by (applications copywrited by their respective owner)…

·         Microsoft Excel

·         Microsoft Visual Basic

·         National Instruments LabView

·         C++, C#

·         MatLab

·         Embarcadero Delphi

·         Any other Microsoft Windows application / development system that allows loading / linking functions exported by DLLs (dynamically linked libraries).

 

This DLL is used by RevdataPLUS for all access to Link Standard Data. The equations specified in various places in RevdataPLUS use the same model as accessing data from a user script and/or applications. RevdataPLUS is an excellent tool to gain understanding of the operation of this DLL and Link Standard Data.

 

Windows applications come in two flavors, 32 and 64 bit. LinkData_VB.DLL as a 32 bit DLL and can be used (loaded) by any 32 bit application (but NOT a 64 bit application). LinkData_VB64.DLL as a 64 bit DLL and can be used (loaded) by any 64 bit application (but NOT a 32 bit application).

 

2.0    Installation / Configuration

 

This DLL is installed in the ProLink suite like all other driver DLLs (in the [Drivers] section of the MACHxxxx.INI file). This DLL does not require any specific configuration, nor does it provide any user interface.

4.0    Script Language Commands

 

The following script language commands (shown as script prototypes) are provided by this DLL:

 

 

4.1      Test, Section, and Stop Record Selection

 

·         Function value Open_Test(var value hdl; string name;);

 

Open the test specified. The name must be a fully qualified path name to the test data (i.e. “C:\data\0997\mytest”). The handle (hdl) returned from this function (it is VARed so the handle is passed to the function by reference, not value) will be passed to all the other functions. The handle returned is unique to this call to open_test. You may have as many tests open as you like at the same time. The function returns a 0 if the test was opened successfully. If a value other than 0 is returned, the error code can be passed to the Error_Str function of the script language to convert the code to its textual description.

 

·         Function value Close_Test(var value hdl;);

 

Close a test previously opened with Open_Test. The hdl provided is the handle returned from the previously successful Open_Test call. This function returns an error code (0 if successful).

 

·         Function value Select_Section(var value hdl; value sect= 0;);

 

Using the previously opened test handle (hdl), select the section specified (sect= 0..9999). This function returns an error code 0 if successful.

Note: By default, the 1st record is loaded in this call. If maximum speed is desired and Select_Record is going to be called next, pass the section number (sect) as a negative value (i.e. section 10 would be -10).

 

·         Function value Select_Record(var value hdl; value rec= 0;);

 

Using the previously opened test handle (hdl) and selected section (Select_Section), select the stop record specified (rec>= 1). This function returns an error code 0 if successful.

 

·         Function value Select_Stop(var value hdl; value rec= 0;);

 

Functionally equivalent to Select_Record. This function has been deprecated, use Select_Record.

 

 

·         Function value Select_FirstSect(var value hdl;);

 

Using the previously opened test handle (hdl), select the first section of the test (numerically). This function returns an error code 0 if successful.

 

·         Function value Select_NextSect(var value hdl;);

 

Using the previously opened test handle (hdl), select the next section of the test (numerically). Assumes a previously successful call to Select_FirstSect. This function returns an error code 0 if successful.

 

·         Function value Select_LastSect(var value hdl;);

 

Using the previously opened test handle (hdl), select the last section of the test (numerically). This function returns an error code 0 if successful.

 

·         Function value Select_PrevSect(var value hdl;);

 

Using the previously opened test handle (hdl), select the previous section of the test (numerically). Assumes a previously successful call to Select_LastSect. This function returns an error code 0 if successful.

 

·         Function value Select_Nextstop(var value hdl;);

 

Using the previously opened test handle (hdl), load the next stop RECORD in the currently selected section. Assumes a previously successful call to Select_Section. This function returns an error code 0 if successful.

 

·         Function value Select_Prevstop(var value hdl;);

 

Using the previously opened test handle (hdl), load the previous stop RECORD in the currently selected section. Assumes a previously successful call to Select_Section. This function returns an error code 0 if successful.

 

·         Function value Select_SectStop(var value hdl;   // previously opened test handle

value sect;           // section number desired

value stp;);          // STOP number desired

 

Sort all the stops in the open test in section/stop order (on the first call after opening the test), ignoring duplicated and operator invalidated stops. Load the section and STOP number (NOT record number) specified. This function returns an error code 0 if successful.

 

·         Function value Select_Firstall(var value hdl;       // previously opened test handle

value allowdup;);  // allow duplicate stop numbers flag, default is false

 

Sort all the stops in the open test in chronological order and load the first stop. The allowdup flag is specified by the caller as true if records with duplicate stop numbers are to be returned by succeeding calls to Select_Nextall, or if only the last valid record of a set of duplicate stop/section numbers will be returned. This function returns an error code 0 if successful.

 

·         Function value Select_Nextall(var value hdl;);

 

Using the previously opened test handle (hdl), load the next stop in chronological order. Assumes a previously successful call to Select_Firstall. This function returns an error code 0 if successful.

 

·         Function value LD_Find_Rsrc(var value hdl; value Resc;);

 

Using the previously opened test handle (hdl) and a Resource identifier (Resc), return the index associated with that resource.

If 0 is returned, the resource was not found.

If a negative index is returned, this resource name is multiply defined. The abs(index) is still usable but may not be correct.

 

The main use of this system is to remove the mapped channel system (analog channels 100…199). By naming analog channels agreed to names (like “Torque”, “Pressure”, “Speed”, etc.), these channels can be looked up by name instead of numbers.

 

This function allows determining channel and variable numbers by name instead of value. A complete list of resource names are in the Variable Number Reference list for a particular test in the RevdataPLUS help menu.

 

This resource list is created by adding all known resource names to a list. Resource names are…

·         Variable short descriptions.

·         Analog channel long and short descriptions.

·         Mapped analog channel descriptions.

·         ProLink analog symbol names (LinkLogger.DLL only).

·         ProLink $TAG symbols (script supplied data variables).

 

Because resource names come from many sources and the index returned is not associated with the context of its use, duplicate names and indexes will happen.

RevdataPlus uses this resource system. It is used in the “RevdataPLUS_SYS.SPT” library script using the following code to convert strings supplied to “Data_Ex” to indexes supplied to the original “Data” function…

 

   function value Rd_sys_Resolve_Resource(string var rname; value err;);

   begin

      result:= StrVal(Str:= rname, Def:= 0);       // if a number is supplied, just use the number

      if result<> 0 then exit;

      // else see if we can convert the supplied string to a number

      result:= abs(LD_Find_Rsrc(Hdl:= revhndl, Rsrc:= rname)); // abs so even if multi-defined it's ok

      if result = 0 then Set_Error(Err:= err);  // if can't find the name, throw the error number provided

   end;

 

   // same as "data" but takes possible resource strings from user

   function value Data_EX(string Vari; string chn= '0'; string unt= 'unitless';);

   value fvari;

   value fchn;

   begin

      fvari:= Rd_sys_Resolve_Resource(Rname:= vari, Err:= -5030); // Vari resource name not found

      fchn:= Rd_sys_Resolve_Resource(Rname:= chn, Err:= -5031);   // Channel resource name not found

      if fvari<> 0 then result:= Data(Vari:= fvari, Chn:= fchn, Unt:= unt);

   end;

 

   // same as "datastr" but takes possible resource strings from user

   function string DataStr_EX(string Vari; string chn= '0';);

   value fvari;

   value fchn;

   begin

      fvari:= Rd_sys_Resolve_Resource(Rname:= vari, Err:= -5030); // Vari resource name not found

      fchn:= Rd_sys_Resolve_Resource(Rname:= chn, Err:= -5031);   // Channel resource name not found

      if fvari<> 0 then result:= DataStr(Vari:= fvari, Chn:= fchn);

   end;

4.4      Raw Data

 

·         Function value Seek_Rawtime(var value hdl;      // previously opened test handle

value tm;             // time to seek into data

string unt;);           // unit for seek time, default = ‘sec’

 

Seek into the raw data (raw stop data AND global slow data) to the time specified (referenced either raw or global start times (vari 757, 787) and raw or global end times (vari 758, 792)). An open test handle must be provided. This function returns the error code 0 if successful (actually, this command just sets an internal variable to the time provided (used by both the raw data and global slow data readers), the only error possible is “unit class mismatch” if an invalid unit is passed in). To determine what this time was last set to, use variable 756 or 786 (both will return the same value).

 

·         Function value Low_Pass(value val;            // incoming value to filter

value srate;          // sample rate in Hz of incoming data (required)

value freq;           // desired filter cutoff frequency in Hz

var string filtstr;);  // filter history string

 

This function is used to apply a low pass digital filter to a series of values recorded at regular time intervals.  Val is an unfiltered value in the sequence to be filtered. Freq is the cutoff frequency of the single pole digital RC type filter. The filter function must know the incoming data sample rate, which is specified by srate. The VARed string ‘filtstr’ maintains the filter history; it should be cleared to null prior to the first call, and passed back to this function unmodified on subsequent calls, on a per channel basis. Clearing filtstr resets the filter. Low_Pass returns the filtered value as the function result.

 

·         Function value Scan_Raw(var value hdl; string cmd;);

 

Using the previously opened test handle (hdl), section, stop, scan the raw data from the current raw position (set by Seek_rawtime or Scan_raw) to a point where the selected analog channel data is above or below a threshold value. If the threshold is found, this function returns a 0 in the function result and sets the Seek_Rawtime (this time can be read by reading variable 756 or 786 with the appropriate channel) to the point in the raw data where the threshold was reached (this time will be interpolated between samples); otherwise, an error code is returned. The command string (cmd) contains commands as shown below:

 

STIME=

Scan time, number of seconds to move forward (if value positive) or backward (if value negative) from the current rawtime position (set by Seek_Rawtime or Scan_Raw) while searching. Default is 0 (use the single data sample at seek position).  If the value exceeds the beginning or end of the raw stop data, an out of bounds error is returned.

ABOVE

Scan until a value above the threshold is found (default if neither is specified).

BELOW

Scan until a value below the threshold is found.

GSLOW

Scan the Global Slow Data (else the currently selected stop’s raw data).

THR=

The threshold value to scan for.

CHN=

Channel number to use while scanning (may be a mapped channel).

UNT=

Engineering unit of the threshold value (res).

FILT=

Low pass the data to this frequency while processing

LPASS=

Same as “FILT” above.

LPOLES=

Number of poles in the low pass filter (default is 1, can be 1, 2, 4, 6, 8 or 10).

HPASS=

High pass the data to this frequency while processing.

HPOLES=

Number of poles in the high pass filter (default is 1, can be 1, 2, 4, 6, 8 or 10).

NOTCH

If specified, the high and low filters specify a notch filter (all frequencies between the high pass frequency are REMOVED). Else, a bandpass filter is assumed.

BANDPASS

If specified, only data between the low pass frequency and high pass frequency will be passed though. This is the default case if NOTCH is NOT specified.

 

Example:

    

    err:= Scan_Raw(hdl:= thand, cmd:= “chn=101 thr=100 unt=lb*ft stime=1”);

 

This will scan the torque channel (channel 101) from the current seek position (variable 756) forward for 1 second (stime) until either the torque channel is above 100 lb*ft (function returns a 0 and the current seek time will be set to the threshold exceeded position) or 1 second of data has been searched (stime) or the end of the data has been reached before stime elapsted (function returns an error code and the seek time is unchanged). 

 

·         Function value Process_Raw(var value hdl; string cmd; var value res;);

 

Using the previously opened test handle (hdl), section, stop and Seek_Rawtime, process the raw data for the selected analog channel for the selected times for a min, max or average value. The ‘var’ parameter (res) is used to return the requested value. The function returns an error code or 0 if no error occurs. The command string (cmd) contains commands (multiple commands are separated by a space) to instruct the routine what to do.  The various commands are:

 

STIME=

Scan time, number of seconds to move forward (if value positive) or backward (if value negative) from the current rawtime position (set by Seek_Rawtime or Scan_Raw) while searching. Default is 0 (use the single data sample at seek position).  If the value exceeds the beginning or end of the raw stop data, an out of bounds error is returned.

MAX

Return the maximum value found in scan (default if neither MIN, MAX, or AVG specified). The Seek_Rawtime value is left at the position the max value was found.

MIN

Return the minimum value found in scan. The Seek_Rawtime value is left at the position the min value was found.

AVG

Return the average value of all samples found in the scan.

AVGDIST

Return the average value of all samples found in the scan by DISTANCE (requires a valid speed channel in the raw data).

GSLOW

Scan the Global Slow Data (else the currently selected stop’s raw data).

CHN=

Channel number to use while scanning (may be a mapped channel).

UNT=

Engineering unit of the resultant value (res).

FILT=

Low pass the data to this frequency while processing.

LPASS=

Same as “FILT” above.

Note: If filtering is specified, the data is scanned prior to the specified times to allow the filters to settle out. 

LPOLES=

Number of poles in the low pass filter (default is 1, can be 1, 2, 4, 6, 8 or 10).

HPASS=

High pass the data to this frequency while processing.

Note: If filtering is specified, the data is scanned prior to the specified times to allow the filters to settle out.

HPOLES=

Number of poles in the high pass filter (default is 1, can be 1, 2, 4, 6, 8 or 10).

NOTCH

If specified, the high and low filters specify a notch filter (all frequencies between the high pass frequency are REMOVED). Else, a bandpass filter is assumed.

BANDPASS

If specified, only data between the low pass frequency and high pass frequency will be passed though. This is the default case if NOTCH is NOT specified.

ROTAVG=

Rotationally average the raw data to the revolutions provided before processing. This is similar to the FILT above but averages a number of samples about each point by the time specified by the current rotational speed. For example, with ROTAVG=0.5 and the machine running at 60 rpm (1 rev/sec), all raw data points used for processing will be an average of 0.25 second about the time point. This allows removing all noise above the fundamental rotational frequency of the machine.

 

Example:

    

    err:= Process_Raw(hdl:= thand, cmd:= “chn=101 unt=lb*ft stime=1 max”, res:= raw);

 

This will scan the torque channel (channel 101) from the current seek position forward for 1 second, looking for the maximum value, and returns it in the local variable ‘raw’. For efficiency, this function computes the min, max and averages simultaneously if any of the four possible commands are given. All three results are then queued in the DLL. If Process_Raw is called again and the test/section/record have not changed, the answer is immediately available (no data scan is required).

 

Filtering:

The data can be filtered a number of different ways. If the legacy FILT=xx command is used, the data will be low pass filtered using 1 pole at the specified frequency (this is the same as using LPASS=xx and LPOLES= 1). Two filters are provided (LPASS and HPASS).

 

·         Function Array_Raw(var hdl: int32; var arr: psafearray; cmd: ansiptr): int32;

 

This function allows reading raw data from a stop and returning the data to the user via a user created ‘SafeArray’ (a Windows / VB aware array type) or script system array (see Array_Value_Open). Because all the points are handled within the DLL, it is VERY fast. The Link Excel add-in uses this function (Visual Basic users can edit a spread sheet containing a raw data table to see how this command is used, Delphi programmers can see/use the pascal unit (LinkData_Inf.pas) provided in the same folder as this help document). The overall philosophy is to create a safearray, call this command, use the data returned in the safe array as desired, then destroy the safearray. The parameters required by this command are…

 

Hdl: Handle to a opened test (provided by the Open_Test routine (a section and stop record must be previously selected).

Arr: Pointer to a previously created Safearray (two dimensional, bounds[0]=number of samples (rows), bounds[1]= number of channels (columns)).

Cmd: Asciiz string containing commands…

 

CHN=

Channel list to be returned in the format CHN=nnn:unit,nnn:unit etc.

Example:

CHN=0:sec,101:lb*ft,103:psi  Will return 3 channels (time, pressure and torque). The array MUST be created with bounds[1]= 3 (for 3 channels). If the channel number is zero, raw data time will be returned for that column of data.

Up to 15 different channels may be specified.

FILT=

All channels (except time) will be LOW PASS filtered to this frequency (hz) (1 pole).

LPASS=

All channels (except time) will be LOW PASS filtered to this frequency using LPOLES number of poles (poles default = 1).

LPOLES=

Define the number of poles in the LPASS filter (1 to 8).

HPASS=

All channels (except time) will be HIGH PASS filtered to this frequency using HPOLES number of poles (poles default = 1).

HPOLES=

Define the number of poles in the HPASS filter (1 to 8).

STIME=

Scan time (sec). Data will be scanned forward or backward from the current raw data position (Seek_RawTime). If NOT specified, data from the current raw data position to the end of data will be returned.

RATE=

Output rate (hz) of desired output data (optional, default= 0).

GSLOW

Read global slow data.

ROTAVG=x

Rotationally filter all returned data to the frequency specified.

MOVAVG=x

Moving average all returned data to the frequency specified.

 

The array provided will be filled depending on the value of RATE…

RATE = 0:

The array provided will ALWAYS be completely filled by data spanning STIME. This means that the incoming sample rate is NOT tied to the output data / sample rate. This allows full decimation of the data. For example, if an apply has 10000 samples at 1000 hz (10 seconds of data) and you provide an array containing 20000 rows, every other row will be an interpolation between actual samples. If you provide a 5000 row array, every other actual data sample will be skipped. All actual data samples pass through the channel filters allowing you to prevent flat out sample skipping. To get all the data without decimation, dim your array to the sample size of the data (use variable 752), seek to the start of the data (variable 757) and leave STIME unspecified or set STIME to the data run time (variable 758 – variable 757) and don’t set the filter or set the filter to 0.

 

RATE > 0:

The array provided will may or may not be completely filled by data spanning STIME. The data will be output at RATE. This rate may or may not be the incoming sample rate. This allows full decimation of the data. If the array is larger than the available data (either off end of the data or STIME is satisfied), the bottom portion of the array will NOT be filled. If the array is smaller than the available data, no error will be reported and data will be returned up to the point the array ran out.

 

Filtering:

The data can be filtered a number of different ways. If the legacy FILT=xx command is used, the data will be low pass filtered using 1 pole at the specified frequency (this is the same as using LPASS=xx and LPOLES= 1). Two filters are provided (LPASS and HPASS).

If a notch filter (remove data between 2 frequencies) is desired, set the LPASS frequency lower than the HPASS frequency (frequencies between the two is removed).

If a band pass filter (pass data between 2 frequencies) is desired, set the LPASS frequency higher than the HPASS frequency (frequencies between the two is passed).

 

Notes:

LinkData_VB.DLL:

When used in this environment, this command will fill the array provided (data will be re-sampled to fit the output size). The DLL cannot change the size of the array passed in.

LinkData.DLL:

When used in this environment (script), this command will fill the array provided (is there are greater then 0 rows in the script array) OR resize the array to fit the size of the data (if there are 0 rows in the script array).

 

·         Function Transform_Raw(var hdl: int32; var arr: psafearray; cmd: ansiptr): int32;

 

This function is ONLY available in the LinkData_VB.DLL. It allows reading raw data from a stop, transforming it to a bucketized format, and returning the data to the user via a user created ‘SafeArray’ (an windows aware array type). Because all the points are handled within the DLL, it is VERY fast. The Link Excel add-in uses this function  The overall philosophy is to create a safearray, call this command, use the data returned in the safe array as desired, then destroy the safearray. This command outputs a table of X/Y data with X and Y(s) being analog channels. It is intended to output a table of analog channels based on another analog channel. This command ‘bucketizes’ the Y channels to the X channel. The safe array is defined as a row (bounds [0]) and column (bounds [1]) 2 dimensional array. The columns are the channels (column 0 is the X channel and columns 1..n are the Y channel(s)). The rows are the ‘buckets’ to place the average Y data in. Column 0 is filled with values linearly interpolated from MIN to MAX. The raw data is then time scanned from the STIME and Seek_RawTime provided. The X channel is read to determine the bucket to use (column 0) then all the Y channels are read and averaged into the appropriate bucket. If the X channel’s value exceeds the MAX or is less than the MIN, the sample is ignored (no bucket available). If a bucket is never used, the returned value for all values associated with that bucket will be zero. The commands used by this command are…

 

Hdl: Handle to a opened test (provided by the Open_Test routine (a section and stop record must be previously selected).

Arr: Pointer to a previously created Safearray (two dimensional, bounds[0]=number of buckets, bounds[1]= number of channels (including the X channel)).

Cmd: Asciiz string containing commands…

 

 

CHN=

Channel list to be returned in the format CHN=nnn:unit,nnn:unit etc. The first channel specified is the X channel (MIN and MAX are referenced to this channel). The following channel(s) are the Y channel(s).

Example:

CHN=23:degrees,101:lb*ft,103:psi  Will return 3 columns of data. Column 1 will contain values from MIN to MAX. Columns 1 and 2 will contain the average of all the raw data samples that fell in the bucket of column 1.

Up to 15 different channels may be specified.

MIN=

Minimum. This defines the value of the first bucket. Defined in the units used to define the 1st channel in the channel list above.

MAX=

Maximum. This defines the value of the last bucket. Defined in the units used to define the 1st channel in the channel list above.

FILT=

All channels (including time) will be filtered to this frequency (hz). Be aware that sloping of the data WILL occur with filtering. If the X channel is rotary position (0 to 359 degrees), this slope effect will make 0 and 360 degrees never appear in the output array and falsely place the fast sloping data in the wrong buckets.

STIME=

Data will be scanned forward or backward from the current raw data position (Seek_RawTime). If NOT specified, ALL raw data available will be used.

INTERP

Goes through all buckets and interpolates bucket values (buckets with no samples) based on the surrounding buckets.

GSLOW

Read global slow data.

 

Note: This command tries to average samples from one (or more) channels into buckets associated with another analog channel. If there are no samples found that go into a particular bucket, that bucket WILL be returned zero (unless ‘INTERP’ is specified in the command string). The data should be sampled at a rate that guaranties that there are samples for all buckets available.

·         Coalesce all like (same engineering unit) channels together into 1 peak trace.

·         Curve-fit the data (normalizes and flattens the trace).

·         Finds peaks with relatively sharp leading and trailing edges.

·         Sort all peaks in decending order.

 

This allows multiple TRUE peaks to be detected without reporting peaks in side-by-side frequency buckets or bunched up. Only truly significant peaks are reported.

·         Function value Array_Snd (var hdl: int32; var arr: psafearray; cmd: ansiptr): int32;

This function is ONLY available in the LinkData_VB.DLL. This function allows reading all the spectral data for a stop record and channel into a user created ‘SafeArray’ (a windows aware type). Because the data reading is all done at one time in the DLL for all the points, it is VERY fast. An error code is returned by this function (0= ok). To use this function, follow these steps…

1.     Open the test (if not already open).

2.     Select section (if not already selected).

3.     Select a stop (if not already selected).

4.     Create the safearray. This array MUST be the exact size required. Use variables 1129 (number of traces) and 1128 (number of buckets per trace) to dimension the array. Columns are traces, rows are frequencies (dimensioned as [rows, cols]).

5.     Call this function passing the test handle, array and command string. The command string can contain any of the following commands separated with a space…

a.     CHN=0:hz             If included, the first column returned will contain the frequencies of the buckets (make sure the array is dimensioned with this extra column in mind).

b.     CHN=n:unit           Defines the channel (n) and engineering unit (unit) desired.

c.     SPEC=n               Specify the trace (a single spectrum from the waterfall) to export to the array. When using this mode, there is only 1 output column.

d.     SPEC=PEAK        Returns a peak spectrum of all available spectrums for this channel. When using this mode, there is only 1 output column.

e.     SPEC=AVG          Returns an average spectrum of all available spectrums for this channel (each output frequency bucket’s value is the average of all saved spectrums for that frequency bucket). When using this mode, there is only 1 output column.

f.      SPEC=ALL           Return all spectrums for the specified channel. If SPEC is not specified, this is the default.

Examples:

1.     “CHN=2:db” Returns a multi-column array containing all the spectrums of channel 2.

2.     “CHN=2:db CHN=0:HZ” Returns the frequencies in column 1 and all the spectrums in columns 2 and up.

3.     “CHN=2:db CHN=0:HZ SPEC=1” Returns a 2 column array with the frequencies in column 1 and spectrum 1 in column 2.

4.     “CHN=2:db CHN=0:HZ SPEC=PEAK” Returns a 2 column array with the frequencies in column 1 and the peak of all spectrums in column 2.

 

·         Function value Spctrm_LPO(Value Hdl; Value Chn; String Freqs; String Times; Var Value Res);

This function returns (via Res) the sound pressure (known as LP) level of a spectrum or spectrums of a channel over a frequency range and time range (if waterfall). The function result is 0 if no error or an error number (use Error_Str to expand to a textual description). The parameters are…

Hnd: Previously opened test handle (a section and stop must also be previously selected).

Chn: Sound channel number (1..n).

Freqs: String containing nothing (all frequencies used) or a range of interest (i.e. “1000..10000”).

Times: String containing nothing (all spectrums used) or a range of interest (i.e. “0..3” or “1”).

Note: If a time is specified outside the range of available spectrums, the 1st, last or only spectrum is used.

Res: The result (in dB) will be placed in this variable.

 

The LPO (sound pressure level) is…

 10*log((10^(db[1]/10))+ (10^(db[2]/10))+ (10^(db[3]/10))+..+ (10^(db[n]/10)))

 

This equation is the sum of the powers of each bucket (dB[n]) over the frequency range specified. If multiple spectrums fit the time range specified, the returned result is the maximum LPO seen processing all applicable spectrums.

 

·         Function value Spctrm_LPO_Avg(Value Hdl; Value Chn; String Freqs; String Times; Var Value Res);

This function works exactly as Spctrm_LPO above except: the returned result is the average LPO seen processing all applicable spectrums.

4.7      Pad mapping functions

The ProLink system supports a Pad Mapping system (requires the Link Pad Mapping machine to measure test parts (pads)). A file is assigned to each part (most tests have 2 or more pads (inside and outside pad and a single rotor, for example).

 

The pad map data file(s) (per pad/file) consists of…

 

o    POI (points of interest). These points are decided by the user as locations on the pad that are to be thickness measured.

·         Each PIO contains 1 or more readings (index 1 is the initial, 2..x are mid readings, the last reading is the final reading). Ideally, all POIs have the same number of readings and a reading was taken for each POI at the same time.

o    Mass (weights). There is an optional mass (weight) measurement for each reading.

 

The following function allows retrieving measurements from previously scanned pads.

‘res’ returns a single specific pad scan reading. This could be 0 (value not determined, POI out of range or any other error) or a value scaled to the unit specified. If no unit is specified, the value returned is either inches (thickness reading) or lbs (mass reading).

 

The Cmd parameter specifies the data value desired (may contain any of the following, in any order, separated by spaces)…

                                                                            

MAX

Return the MAXimum of all the POI(s), MASS(s), READING(s) specified. This will return an actual, single reading of READING and POI does not specify a range.

 

MIN

Return the MINimum of all the POI(s), MASS(s), READING(s) specified. This will return an actual, single reading of READING and POI does not specify a range.

 

AVG

Return the AVeraGe of the POI(s), MASS(s) and/or READING(s) specified. This will return an actual, single reading of READING does not specify a range. If neither MAX or MIN is specified, average is assumed.

 

POI=1

Specified a POI index number (1..n). A range can be specified (i.e. “READING=1”, “READING=1..5”, “READING=1,2,5..7”). If this parameter is NOT specified, ALL POIs will be looked at.

 

READING=1

Specified a reading index number for MASS(s) or POI(s). A range can be specified (i.e. “READING=1”, “READING=1..5”, “READING=1,2,5..7”). If this parameter is NOT specified, ALL readings will be looked at.

 

MASS

Return a mass reading. Use READING to specify the reading(s) to return the MAX, MIN or AVG of. If used, the POI command is ignored. If NOT specified, POI readings are assumed.

 

UNT=myunit

This command specifies the engineering unit to return values in. The default unit (if not specified) is inches (i.e. UNT=MM, UNT=inch or UNIT=lb, etc.).

“avg unt=in POI=1..10 reading=1..10”

Using POIs 1 through 10, return the average (inches) of readings 1 through 10 (up to 100 readings averaged).

 

“max unt=in POI=1..10 reading=1..10”

Using POIs 1 through 10, return the maximum (inches) of readings 1 through 10 (up to 100 readings looked at).

 

“max mass unt=lb reading=1..10”

Return the maximum (lbs) of the readings 1 through 10.

 

“avg mass unt=lb reading=1”

Return the 1st reading (lbs). Note that Avg/min/max mean nothing for 1 reading.

 

“”

This is uses all the default settings, return the average of all the readings from all the POIs in inches.

 

“mass”

This is uses all the default settings, return the average of all the MASS readings in lbs.

7.0    LinkData Errata Processing

 

Ideally, collected data would be accurate. Unfortunately, mistakes happen during test setup / machine calibration / etc. The LinkData.DLL contains a system to correct previously recorded data without really changing the data. When a test is opened, the test folder is searched for a file named “Errata*.INI” (note the asterisk (*), this allows the file to have any name as long as it starts with “Errata” and ends with “.INI”). The 1st of these files found is loaded (only 1 should be in the test folder). If this file is deleted at a later date, all data reverts back to original values. Below is an example of file contents…

 

; Data errata corrections

[Channel_scaling]

23=M=43908 B=-23 unt=°F

24=M=43908 B=-23 unt=°F

25=M=43908 B=-23 unt=°F

26=M=43908 B=-23 unt=°F

27=M=43908 B=-23 unt=°F

28=M=43908 B=-23 unt=°F

29=M=43908 B=-23 unt=°F

30=M=43908 B=-23 unt=°F

 

[Value_variables]

51_a    = value=0 unt=psi chn=102

51_b    = value=0 unt=psi chn=103

108     = value=1.234 unt=slug·ft²

500     = value=12.85 unt=inch

1131    = unt=db offs=55 chn=1

10158   = unt=sec value=2 sect=1 recrd=2

10158_A = unt=sec value=3 sect=1 recrd=3

10158_B = unt=sec value=4 sect=1..10,200 recrd=4..20

 

[String_variables]

456 = string='New 456'

441 = string='New description' chn=109

In the above examples…

·         The 1st line is a comment (all lines starting with “;” are comment lines).

·         The temp channels WILL be rescaled (channels 23..30).

·         Average by revs (51) of channels 102 and 103 will return 0. Note: The “_a” after the 51 variable number allows multiple 51s under the same key (“Value_variables”). Each item under a key must be unique.

·         Fixture inertia (108) will return 1.234 slug_ft².

·         Rolling radius (500) will return 12.85 inches (all data items that rely on rolling radius will change).

·         NVH channel 1 (1131) will have 55 db added to it.

·         Header string variable will always return “New 456”.

·         Channel description (441) for mapped channel 109 will always return “New description”.

·         Dyno description (957) will always return “My dyno”.

·         Variable 10158 is multiply defined with different section, record ranges and values.

 

The file may contain various [sections], these are described as…

·         [Channel Scaling]

Change the fullscale (or multiplier) of channel(s). Each line in this section contains an actual physical channel number (no mapping allowed) and a new M, B and unit. While the test is open in LinkData, channels specified here WILL have these fullscales.

Keys…

1.    m: This is the new fullscale (or multiplier) for the channel.

2.    b: This is the new fullscale offset for the channel.

3.    unt: Values here are in this unit.

 

NOTE:

Because Link_Logger data is stored as values (not AtoD values that require scaling), the M and B provided here are MULTIPLIERs and OFFSETs of the original data.

 

·         [Value_variables]

Change any single numeric variable. The change affects the ENTIRE test.

Keys…

1.    value: Set result to this value.

2.    mult: Multiply read value by this (done 1st).

3.    offs: Add this value to the read value.

4.    unt: Values here are in this unit.

5.    chn: Look at this channel.

6.    sect: Pertains to just this section list (i.e. “1..10”, “1,2,3,100..200”).

7.    recrd: Pertains to just this record list (i.e. “1..10”, “1,2,3,100..200”).

Keep in mind, any errata scaling of analog channels is done BEFORE this function.

 

·         [String_variables]

Change any single string variable. The change affects the ENTIRE test.

1.    string: Set result to this string.

2.    chn: Look at this channel.

3.    sect: Pertains to just this section list (i.e. “1..10”, “1,2,3,100..200”).

Notes: If loss torque is unavailable, this variable reports exactly the same value as 113 below. This value may not compute accurately on some classes of machines (SAE2, TO4 machines) if non-standard data processing is performed on the machine.

113       Calculated BRAKING inertia (inertia seen by the brake(s)): Uses average torque (v51, chn101 or chn101+chn131 if dual mode), initial speed at start of averages (v54), final speed at end of averages (v55) and time of averages (v47 – v49) to determine the inertia actually seen by the brake. This is the same as variable 112 EXCEPT ignores the loss torque (so just the inertia the brake actually saw is reported). On chassis coupled machines, this variable will report an inertia in linear (e.g. lb, kg) units.

Note: This value may not compute accurately on some classes of machines (SAE2, TO4 machines) if non-standard data processing is performed on the machine.

114       Loss torque: During each apply, this value is computed as an average loss is computed by looking up the torque loss at the current speed 100 times a second from the coast down profile. This approximates the torque decelerating the machine that is NOT measured brake torque. Notes: Losses may change during the test with the temperature of the bearings; this average loss is as accurate as the losses are consistent. When using Inertia Simulation, losses are automatically removed and possibly accurately added back to the system (if Isim_loss_comp is off).

115       Target Inertia Setpoint: This computed value is either v502 (mounted inertia, Isim off) + Wheel inertia (v570) or the inertia simulation setpoint (Isim On).

·         Distance(i.e. ft): If a distance unit is specified, the elapsed distance is returned.
